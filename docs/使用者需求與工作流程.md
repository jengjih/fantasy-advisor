# 使用者需求與工作流程（給 Claude Code 看的交接文件）

> 寫於 2026-10-30（台北）。這份文件整理了使用者在手機雲端對話裡的需求、常見的請求類型，
> 以及每一類請求該怎麼處理。`CLAUDE.md` 是規則和背景，`data/advisor_notes.md` 是每週的戰況和決定，
> 這份文件說明**使用者想要什麼、該怎麼幫他**。三份都要讀。
> repo 是公開的：這裡不寫金鑰、Email 或任何個資。

---

## 1. 使用者是誰、怎麼跟他溝通

- **AI／程式新手，也是 fantasy 籃球新手。** 用白話繁體中文，一步一步帶。他會用簡體中文或繁體中文打字，回覆一律用繁體中文。
- **主要用手機**（Claude App 的 Code 分頁）。每次對話通常會：傳 Yahoo 截圖 → 問問題 → 切去別的 App → 等通知再回來看。
- **時間一律講台北時間。** NBA 和 Yahoo 的比賽日是美東時間，台北早上的比賽＝美東前一天。換人、排先發都要寫「台北幾點以後、幾點以前」。
- **要結論，不要選擇題。** 他問「到底要不要換？」時，直接回答「換／不換」、什麼時候換、怎麼操作。理由寫在後面，最多幾行。
- **要客觀。** 他會問「你對我有信心嗎？客觀回答」這類問題，要給數字和優缺點，不要只講好聽話。
- **會質疑，也會拿別的工具交叉比對。** 例如「我用電腦模型算，好像沒那麼樂觀」「Brunson 很猛欸」。遇到這種情況要重新驗證，算錯了就直接承認哪裡錯、修正。
- **只給建議，不幫他按。** Add/Drop、排陣、交易都是他自己在 Yahoo 操作。要寫清楚在 Yahoo 的哪一頁、按哪個按鈕。
- **不用付費服務。** 除了 Pro 訂閱，什麼都不用付費。不要推薦要額外付費的 API、外掛或方案。外掛如果有付費功能，要講清楚。
- **每次回覆的最後一步要推手機通知（PushNotification）。** 一行、先講結論。一定要等回覆全部寫完才推，太早推他收不到。他明確要求過，也測試過。
- **指令要中文。** 他覺得中文比較好記，所以 `/sync` 已經改名成 `/同步`。

## 2. 終極目標：兩個聯盟都贏宿敵

使用者和宿敵在兩個聯盟都有約定。**只贏一個等於沒贏，兩個都要贏。**接下來所有的建議，都以這個目標為最優先。

| 聯盟 | 宿敵 | 目前勝算（10/30 模擬） | 重點 |
|---|---|---|---|
| 誰是懂球帝（8 隊、11 項） | 尚恩·李文斯頓 | 不串流 30%；每週多打 6 場約 78–80%；加上 Brunson 換 Jalen Johnson 約 84% | **勝負關鍵是每週用滿 8 adds** |
| baek's Grand League（12 隊、9 項） | 安卓·伊古達拉 | 約 99%（他進季後賽只有 8%） | 守住：不跟伊古達拉交易、不幫他補強 |

- **「贏」的定義還沒確認。** 目前假設是「季末最終名次（含季後賽）排在宿敵前面」。使用者回覆後，更新這裡和 `advisor_notes.md`。
- **尚恩的破綻**（使用者自己發現的）：第 2 週他只用了 1 次 add。要請使用者每週截一張尚恩的 Team 頁，看他用了幾次 adds。他如果開始認真串流，我們的優勢會縮小。
- **尚恩的弱項**：FT%、3PTM、3PT%、TO。強項：AST、REB、BLK、FG%，因為他的長人和組織後衛很多。
- **使用者兩個聯盟共同的弱點**：命中率高、會搶籃板的長人。簽人和交易都以這類球員為優先。
- 誰是懂球帝季後賽同戰績時，比的是「兩隊直接交手的戰績」，所以**跟尚恩直接對戰的那幾週特別重要**。

## 3. 使用者會提出的請求類型，以及怎麼處理

### A. 同步截圖（最常見）
- **他會怎麼說**：打 `/同步` 再附截圖，或直接丟截圖。截圖包括 Matchup、My Team、對手 Team、Players（FA 名單）。
- **怎麼做**：照 `.claude/commands/同步.md` 的步驟：存資料 → 查傷病 → `plan.py` → 更新筆記 → `sync.py` → 回報 → 推通知。
- **注意事項**：
  - 先判斷是哪個聯盟。8 隊、有 FGM 和 3PT% 的是誰是懂球帝；12 隊、9 項的是 baek's Grand League。
  - **名字縮寫容易搞混**，要看球隊再決定是誰：
    - A. Thompson：HOU 是 Amen，DET 是 Ausar
    - M. Bridges：PHX 是 Miles，NYK 是 Mikal
    - K. George：UTA 是 Keyonte，WAS 是 Kyshawn
    - A. Wiggins：MIA 是 Andrew，ATL 是 Aaron
    - D. Mitchell：CLE 是 Donovan，MIA 是 Davion
    - 另外，Jimmy Butler 在資料裡叫「Jimmy Butler III」
  - 截圖不完整時（例如只有下半部、沒有隊名），不要猜，直接問他。
  - 截圖看不出某個動作做了沒（例如換人），要問，不要假設。
  - Yahoo Matchup 頁的「Games Played 剩餘」只算目前排先發的人，會低估場次。剩餘場次以賽程計算為準。

### B. 戰況、本週勝率
- **他會怎麼說**：「目前戰況如何？」「本週樂觀嗎？」「我用電腦算好像沒那麼樂觀」
- **怎麼做**：跑 `uv run python plan.py`，最後的「🎲 勝率模擬」會算出不換人、照規劃換人兩種情況的本週勝率。
- **要回報的內容**：
  - 目前比分
  - 預測結算比數
  - 本週贏的機率
  - 搖擺項，附上各項贏的機率
  - 對手剩下幾場、有哪些球星還沒打
- **教訓**：不要只看目前比分就說樂觀。10/29 我只看比分就說「8-3 很穩」，結果漏算對手剩下的場次（Curry、Jokić 等人），實際只有約 76%。被使用者抓到。

### C. 簽人、換人（Adds）
- **他會怎麼說**：傳 FA 截圖，問「該簽誰？」「確定要簽 X？」
- **怎麼做**：plan.py 的 Adds 規劃 ＋ `projection.simulate()` 比較不同人選，再補上自己的判斷。
- **一定要包含的資訊**：
  - 釋出誰、簽誰、位置、對手、台北開打時間、補哪些比項、是不是純 FA（綠色 +）
  - **最早、最晚幾點要換（台北時間）**
- **規則**：
  - **Daily-Today 聯盟**：要釋出的人如果當天還有比賽，要等那場打完再換。10/30 就因為這樣，提醒他等 Edey 打完再換。
  - **不要為了多一場就釋出潛力新秀。** plan.py 兩次建議放掉 Dylan Harper，我都沒採用，改放串流位，勝率一樣。
  - **檢查 plan.py 推薦的人命中率高不高。** 它曾推薦 Keaton Wagler，但他命中率只有 .316。改成 Isaiah Jackson 之後，FG% 的贏面從 48% 升到 63%。
  - 不簽 waiver（黃色 +）上的人，也不簽掛 O 或 Q 的人。
  - baek's Grand League 週一到週四原則上不用 adds。
  - 使用者問「11/2 打勇士，還算這週嗎？」這類問題時，用「台北週一早上＝美東週日晚上」來解釋。

### D. 排先發提醒
- 每天提醒把有比賽的人移上先發，尤其是週末，板凳常有人有比賽。
- 要列出：要移上去的人、要換下來的人、最晚幾點前要排好。
- 可以教他用 Yahoo 的「Start Active Players」。

### E. 傷病
- 用 `fetch_injuries()` 從 ESPN 即時抓。要列出雙方陣容裡掛 Out 或 Day-To-Day 的人、預計回歸日，也要確認準備簽的人沒有受傷。
- 常追蹤的人：
  - Luka（背傷，10/30 已經痊癒）
  - Kon Knueppel（baek's 的 IL，回來後要移出 IL，必須先釋出一個人）
  - Jalen Williams、Cason Wallace（預計 2027 年 3 月回來，剛好趕上誰是懂球帝的季後賽，**不要釋出**）

### F. 交易評估
- **他會怎麼說**：「換真的划算嗎？」「到底要不要換？什麼時候換？」，或傳交易截圖。
- **怎麼做**：
  1. 先查兩人的實際數據，本季和上季都看
  2. 用 `rival.py --give ... --get ... --partner ...` 跑季末勝率，**換兩組亂數各跑一次**，確認不是巧合
  3. 用 plan.py 或 simulate 看本週的影響
  4. 確認送出的時間點：這個聯盟交易要投票 1 天；如果交易對象剛好是本週對手，要確認生效時兩人本週的比賽都打完了
  5. 最後給**明確的決定**：要不要換、什麼時候送、被拒絕或對方要求加碼時怎麼辦
- **原則**：
  - 名氣不等於 fantasy 價值。比項聯盟看的是全面性，要用數據解釋（例如 Brunson 和 Jalen Johnson 的比較）。
  - 交易只能多 2–6%，模擬誤差約 ±3%，**不要加碼**。
  - **不要跟宿敵交易。**
- 已經拒絕過的交易：
  - 桐生一馬：Edgecombe + Kawhi + Randle 換 Brunson + Bam
  - 伊古達拉：Jerami Grant 換 Dosunmu

### G. 對手、宿敵分析
- **他會怎麼說**：「分析一下我對手的本週勝率，他的隊伍強嗎？」
- **怎麼做**：用 simulate 算對手那場的勝率，再看他每週各比項贏的機率、戰績、陣容是否平均、傷兵狀況。強弱點要寫進 `advisor_notes.md` 的「宿敵監控」。

### H. 季末預測
- **他會怎麼說**：「季末到底誰會贏？」「越精準越好，需要什麼資料我給你」
- **怎麼做**：
  - `uv run python season.py --league 聯盟一`（或 `聯盟二`），可以加 `--refresh` 重抓整季賽程
  - 資料來源是 `data/league_rosters.json`：全聯盟各隊陣容含 IL、戰績表、本週目前比分
  - 回報每一隊的：預測最終戰績、進季後賽機率、冠軍機率、各比項的強弱
- **要請使用者提供的資料**：
  - 每一隊的 Team 頁，往下滑連板凳、IL 一起截
  - Standings
  - League Settings
  - 自己的整季賽程（Team → Schedule），還沒拿到
- 每 2–3 週更新一次。

### I. 策略發想（以贏宿敵為目標）
- **他會怎麼說**：「幫我想怎麼打敗他」「還有什麼能提升勝率？」
- **工具**：`uv run python rival.py`，可以試算每週多串幾場、做某筆交易之後，最終名次贏過宿敵的機率。
- **已經給過的建議**，依效果大小排列：
  1. 每週用滿 8 adds
  2. 每天排先發
  3. 挑「整個 NBA 比賽少的日子」串流，優先簽籃板多、命中率高的長人
  4. 把 FA 裡受傷但很強的人放進 IL 養著（兩個聯盟都允許）
  5. 季後賽前照賽程佈局（誰是懂球帝的交易截止日是 3/18）
  6. 對上尚恩那週全力打他的弱項
  7. 定期更新資料、重跑預測
  8. 盯 NBA 新聞搶人

### J. 決策請求
- **他會怎麼說**：「幫我下最後決定」
- **怎麼做**：第一行就寫決定，例如「決定：換。現在就送出。」接著寫怎麼操作，再列出照做的規則（被拒絕怎麼辦、對方加碼怎麼辦）。最後把決定寫進 `advisor_notes.md`。

### K. 工具和系統問題
- **他會問的**：「你有什麼功能？」「可以串 Yahoo API 嗎？」「有什麼外掛或 skill 能讓你更聰明？」「這個指令是什麼時候做的？」「通知怎麼沒來？」
- **怎麼處理**：
  - 用白話說明。不知道的事要去查，例如用 git log 查指令建立的時間。
  - Yahoo API 正在等核准，使用者 10/27 送出申請。
  - 外掛只找到 SmartDraftBoard，社群做的，進階功能要付費。

## 4. 工具對照表

| 需求 | 指令或函式 | 說明 |
|---|---|---|
| 同步截圖 | `/同步`（`.claude/commands/同步.md`） | 完整流程 |
| 本週推演和勝率 | `uv run python plan.py [--league 聯盟一] [--allow-weekday]` | 每天出賽、預測比數、Adds 規劃、勝率模擬 |
| 比較不同換法 | `projection.simulate()`、`projection.apply_steps()` | 試算不同陣容的本週勝率 |
| 季末預測 | `uv run python season.py --league 聯盟一 [--runs 2000] [--refresh]` | 全聯盟最終戰績、季後賽和冠軍機率 |
| 宿敵對決 | `uv run python rival.py [--league] [--stream N] [--give A --get B --partner 隊名]` | 串流和交易對「贏過宿敵」機率的影響 |
| 傷病 | `fantasy_advisor.nba_data.fetch_injuries()` | ESPN 即時 |
| 資料存檔 | `fantasy_advisor.state`：`apply_roster_changes`、`save_matchup`、`save_free_agents`、`save_opponent_roster` | 存進 `data/state.json` |
| 推上 GitHub | `uv run python sync.py` | 自動 commit、push `data/`。程式碼要自己 commit |
| 手機通知 | PushNotification | 每次回覆的最後一步 |

資料檔：
- `data/state.json`：我方陣容、本週比分、FA 名單、本週對手陣容
- `data/league_rosters.json`：全聯盟陣容和戰績
- `data/snapshot/season_schedule.json`：整季賽程
- `data/advisor_notes.md`：戰況和決定
